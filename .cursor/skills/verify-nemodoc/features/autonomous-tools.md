# Autonomous file and web tools

Run `npm run verify:agents -- autonomous-tools.spec.ts`. The cross-platform isolated harness builds the real frontend and starts an owned server. The journey creates a separate real Express worker/store and a fresh browser context, uploads a public synthetic Markdown brief through the native file input, grants file/web tools, and runs the personal agent through the normal task API. It verifies file reads, public search and page extraction, a rejected traversal filename, a successful new file, original input preservation, downloaded bytes, durable audit events, reload persistence and mobile overflow. Provider responses are deterministic; saves, permissions, worker execution and browser handlers are real.

For explicitly authorized live calls, set `NEMODOC_AUTONOMOUS_LIVE=1`. The second journey uses the saved Nemotron connection and the Tavily key in ignored `data/autonomous-live.env`. It sends only a synthetic brief and public excerpts, with no mocked inference or search results. API keys are loaded server-side, never filled into traced browser fields. The test records HTTP receipts, model IDs, actual tool outcomes and output metadata in `output/autonomous-live-*`; credentials remain under its ignored `private/` directory. Successful UI screenshots are `workflow.png`, `workflow-detail.png` and `mobile.png`. Live sample success is not proof of general accuracy, rejection robustness.

`tests/agent-tool-security.test.ts` supplies adversarial fixture coverage for unsupported tools/arguments, denied scopes, candidate-only evidence, traversal, links, storage limits, durable output recovery, search revision changes and audit write failures. Keep that separate from live model evidence. The README screenshot should come from the successful live journey and contain no keys or personal material.
