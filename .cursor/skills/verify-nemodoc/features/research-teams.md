# Research teams

Run `npm run verify:agents -- research-team.spec.ts` with the isolated verification harness.

The browser journey uses a fresh context and temporary Express backend. It replaces only provider and optional runtime boundaries with deterministic fixtures. It saves/tests the Tavily connection, approves an original synthetic PDF, generates and edits a team plan, adds/removes researchers, checks stale-plan blocking, and runs application-managed research. It verifies parallel researcher activity, reviewer synthesis, persisted notebook/web evidence, web excerpts, local citation navigation, token usage and trace inspection. A screenshot is retained in `output/research-team.png`; the verification harness retains browser traces and video.

This establishes application behavior with fixtures. It does not prove live Nemotron accuracy, Tavily availability, or NemoClaw containment. Backend tests separately cover legacy NemoClaw routing, cancellation, bounded concurrency, failure, citation isolation, JSON reload, unsafe web addresses and restart recovery. PostgreSQL integration requires isolated database credentials.

A second journey configures and tests three research model profiles through Connections, saves a planner and cost preference, verifies suggested model assignments, overrides one assignment, and executes researchers and the reviewer on distinct model endpoints. It verifies the actual fixture request routes and persisted model choices after reload. Its screenshot is `output/research-model-routing.png`. These are deterministic model fixtures, not live multi-provider quality or price measurements. Unit/API tests cover stale profiles, unknown IDs, failed tool probes, credential masking and routing metadata persistence.

Both journeys also save the final report to Notes, download Markdown, and verify local save state after reload. Research opens by default. Execution settings, per-agent usage, technical logs and scheduled tasks are collapsed until needed; completed reports appear before team details. Unit tests verify citation filtering, partial report export and backward-compatible ZIP backups.

## Optional live MML acceptance

With explicit authorization to send retrieved book excerpts to the saved model provider and incur provider charges, set `NEMODOC_MML_RESEARCH_LIVE=1` and run `npm run verify:agents -- research-team-live.spec.ts`. Supply the local PDF as `data/mml-book.pdf` or `NEMODOC_MML_BOOK`; the test reads only the saved notebook model connection from `data/settings.json`.

The live journey creates a fresh browser notebook and isolated server workspace, uploads the actual book through the UI, generates and reviews a real plan, and lets the normal worker execute the research team. It records each agent's visible assignment/stage/status, checks overlapping researcher spans and subsequent reviewer execution, inspects the persisted trace, navigates a local supporting page, and reloads the UI to verify the report remains recorded. Model calls and responses are never mocked or delayed. Screenshots, video, request timings, observations, workspace and server traces stay in a unique ignored `output/mml-research-live-*` directory. The Playwright browser trace is retained by the standard verification report under `output/verification/`. The test skips unless explicitly enabled; it does not enable web research or load delivery credentials.

For the NVIDIA-family/PostgreSQL acceptance mode, set `NEMODOC_NVIDIA_RESEARCH_LIVE=1` with explicit authorization for book excerpts and inference charges at the configured NVIDIA endpoint. The test reads `NVIDIA_API_KEY`/`NVIDIA_BASE_URL` from local `.env` and isolated database URLs from `NEMODOC_RESEARCH_DATABASE_CONFIG` (default `output/research-live-db.json`, shape `{ "databaseUrl": "...", "readDatabaseUrl": "..." }`). Use a dedicated UTF8 PostgreSQL database and the restricted `agent_reader` role. It tests saved profiles through Connections, records planner/agent/tool events in actual PostgreSQL tables, verifies SQL rows, downloads reports/logs, saves Notes and restarts the backend without replaying inference. Private connection files stay under the evidence directory's `private/` folder and must never be shared or committed.

`NEMODOC_LIVE_SYNTHETIC=1` selects a generated three-page packet instead of the private MML book, while keeping real inference and PostgreSQL. For an explicitly reviewed new plan after a Super provider failure, `NEMODOC_LIVE_RECOVER_DIR` may reference a prior failed acceptance directory: its SQL failure record is audited and Super is excluded from the new plan. The new run still requires visible planning/review and uses Lightning researchers plus Ultra review. This never changes a running agent's route or replays the failed run. Historical failure evidence is retained separately.


Dashboard coverage in `research-team.spec.ts` uses the actual stored fixture traces: period/status/model controls, missing pricing, user-entered estimate rates, inspect/export/navigation, mobile overflow and system reduced motion. Dashboard API unit tests cover scope, missing usage, redaction and time-range validation; PostgreSQL integration verifies deduplicated replay aggregates. UI fixtures are not live model proof.

Agent navigation is **Research / Dashboard / Connections / More**. Secondary runtime monitoring and configuration journeys open **More → Agents** first. The research UI uses state-driven work indicators and compact expandable assignment cards. Dashboard screenshots are `output/agent-dashboard-desktop.png` and `output/agent-dashboard-mobile.png`; active research is `output/research-agents-working.png`.
